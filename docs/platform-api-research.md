# OmniSocial — Platform API ஆராய்ச்சி (தமிழில்)

Single-user, "ஒரே post → எல்லா platforms-லும் publish" dashboard-க்காக 8 target platforms பற்றிய ஆராய்ச்சி, $0 budget-ல் (Vercel Hobby + Vercel Postgres + Vercel Blob) run செய்யும் வகையில். LinkedIn வேண்டுமென்றே விட்டுவிடப்பட்டுள்ளது.

**Methodology குறிப்பு / வரம்பு:** Sandbox-ன் network egress proxy `core.telegram.org`, `discord.com`, `developers.facebook.com`, `docs.bsky.app`, `docs.joinmastodon.org` domains-ஐ block செய்தது (முழு domain block), அதனால் official pages-ஐ எல்லா இடங்களிலும் நேரடியாக fetch செய்ய முடியவில்லை. அப்படி நடந்த இடங்களில், கீழே உள்ள findings web search results-ல் இருந்து (official docs-ஐ quote/paraphrase செய்யும் snippets), official GitHub source repos-ல் இருந்து (`discord/discord-api-docs`, `mastodon/documentation` — raw GitHub content வழியாக, அது block ஆகவில்லை), அல்லது நேரடியாக அணுக முடிந்த Reddit/Bluesky pages-ல் இருந்து எடுக்கப்பட்டவை. ஒவ்வொரு fact-க்கும் அதன் source குறிப்பிடப்பட்டுள்ளது; underlying official text-ஐ நேரடியாக verify செய்ய முடியாத இடங்களில், அதை confirmed என்று காட்டாமல் தெளிவாக சொல்லப்பட்டுள்ளது.

## Telegram — Bot API

- **Official docs:** https://core.telegram.org/bots/api (இந்த session-ல் egress block காரணமா நேரடியா fetch பண்ண முடியல; கீழே உள்ளது இந்த page-ஐ reference பண்ணும் search-engine snippets-ல் இருந்து, மேலும் https://core.telegram.org/bots/faq)
- **Auth method:** Bot token. Setup: Telegram-ல் `@BotFather`-க்கு message பண்ணு, `/newbot` run பண்ணு, prompts-ஐ follow பண்ணு (bot name + username) — BotFather ஒரு token string தரும் (`123456:ABC-DEF...`). இது ஒண்ணு தான் தேவை — OAuth flow, app review எதுவும் இல்ல.
- **Approval/review process:** இல்ல. எந்த bot token-உம் உடனே production-ல வேலை செய்யும். Telegram-ன் anti-spam/flood system மட்டும் தான் gate — அது automatic, review இல்ல.
- **Publish endpoint(s):** Text-க்கு `sendMessage`; image-க்கு `sendPhoto` (optional `caption` text-க்கு) — photo `multipart/form-data`-ஆ upload ஆகும், அல்லது URL/file_id-ஆ pass பண்ணலாம். "title + text + image" post ஒரே `sendPhoto` call-ஆ caption-உடன் map ஆகும்; image இல்லைன்னா `sendMessage` மட்டும் போதும். Bot ஏற்கனவே add ஆன chat/channel/group-க்கு தான் post பண்ண முடியும் (channels-க்கு posting rights தேவை).
- **Delete endpoint:** `deleteMessage(chat_id, message_id)`. Widely-cited documentation summaries படி, bot அது send பண்ண messages-ஐ மட்டும் தான் delete பண்ண முடியும், பெரும்பாலான chat types-ல் ஒரு limited time window-க்குள் (பொதுவா 48 மணி நேரம் என்று சொல்லப்படுது) மட்டும்; bot admin-ஆ இருக்கும் channels/supergroups-ல் restrictions கொஞ்சம் தளர்வா இருக்கலாம். "எப்போதும் delete ஆகும்" என்று dashboard-ல் நம்பும் முன், இதை live API docs-ல் verify பண்ணனும்.
- **Metrics/stats endpoint:** Bot-க்கு மிக limited. Telegram-ல் generic "likes" concept இல்ல. Channel post view counts Telegram client UIs-ல் தெரியும், ஆனா simple Bot API call-ல் reliably கிடைக்காது; message reactions feature இருக்கு ஆனா bot-level aggregate reaction count access இந்த pass-ல் confirm ஆகல — இந்த project-க்கு Telegram-ஐ "Bot API வழியா meaningful engagement stats இல்ல" என்று treat பண்ணுங்க.
- **Rate limits:** ஒரே chat-க்கு தோராயமா 1 message/second (bursts tolerate ஆகும்), bulk sends-க்கு மொத்தமா ~30 messages/second, ஒரே group-க்கு ~20 messages/minute. Limit தாண்டினா `429` + `retry_after` வரும். Paid "Telegram Stars" broadcast tier free 30/sec-ஐ தாண்டி ~1000 msg/sec வரை (message-க்கு ~0.1 Stars) கூட்டலாம் — single-user dashboard scale-ல இது தேவையே இல்ல.
- **Cost:** Free. இந்த use case-க்கு paid tier தேவையில்ல.
- **முக்கிய Gotchas:** **channel**-க்கு post பண்ண bot அந்த channel-ல் admin-ஆ add ஆகணும் (வெறும் "ஒரு chat" மட்டும் போதாது); normal group-க்கு post பண்றது simple. Delete rights/windows message-type/chat-type-ஐ பொறுத்து மாறுவதால், old posts-க்கு "delete" silently fail ஆகும் வாய்ப்பு அதிகம் உள்ள platform இதுவே — success guarantee பண்ணாம "delete முடியல, post பழசா இருக்கலாம்" என்று fallback வைக்கவும்.

## Discord — Bot API / Webhooks

- **Official docs:** https://discord.com/developers/docs/resources/message மற்றும் https://discord.com/developers/docs/topics/rate-limits (direct fetch block ஆனது; கீழே உள்ளது official docs-ன் own GitHub source `discord/discord-api-docs` (`developers/resources/message.mdx`, `developers/topics/rate-limits.mdx`) raw GitHub content வழியா verify பண்ணப்பட்டது).
- **Auth method:** Bot token, **Discord Developer Portal**-ல் create பண்ணனும் (discord.com/developers/applications): application create பண்ணு → **Bot** add பண்ணு → token copy பண்ணு → `bot` scope + permissions (**Send Messages**, **Attach Files**, delete-க்கு **Manage Messages**) வெச்சு OAuth2 invite URL generate பண்ணு → அந்த URL-ஐ வெச்சு உங்க own server/channel-க்கு bot-ஐ add பண்ணு. எளிதான one-way posting-க்கு மாற்று: channel Integrations settings-ல் create பண்ணும் **Channel Webhook** — URL நேரடியா POST பண்ணலாம், bot/OAuth setup எதுவும் இல்லாம. ஆனா webhook மட்டும் இருந்தா bot மாதிரி delete/reactions read flexible-ஆ முடியாது — அதனால் bot token தான் இங்க better fit.
- **Approval/review process:** உங்க own server(s)-ல் மட்டும் bot use பண்ணா இல்ல. Discord-ன் "Verification"/"unusual growth" gates 75+ guilds-ல் bot add ஆனா தான் வரும் — single-user dashboard-க்கு irrelevant.
- **Publish endpoint(s):** `POST /channels/{channel.id}/messages`. Text `content` field-ல் போகும்; image `multipart/form-data`-ஆ `files[n]` part + attachment metadata describe பண்ணும் `payload_json` part-ஆ attach ஆகும் (attachment `id`, file index `n`-உடன் match ஆகணும்).
- **Delete endpoint:** `DELETE /channels/{channel.id}/messages/{message.id}`, bot-க்கு `MANAGE_MESSAGES` தேவை (சில contexts-ல் own messages அந்த permission இல்லாமலும் delete ஆகும், ஆனா அதை கொடுத்தா edge cases தவிர்க்கலாம்). Rate-limits doc படி, delete-message calls-க்கு தனி, அதிக generous bucket இருக்கு (moderation-style bulk deletes நல்லா வேலை செய்ய).
- **Metrics/stats endpoint:** Discord-ல் "likes/shares" concept இல்ல. அதுக்கு நெருக்கமான equivalent **reactions** — `GET /channels/{channel.id}/messages/{message.id}/reactions/{emoji}` ஒரு emoji-க்கு react பண்ணின users-ஐ list பண்ணும், message object-ல் per-emoji counts கொண்ட `reactions` array இருக்கும். Native "comment count" இல்ல (replies channel-ல் வேற messages-ஆ தான் இருக்கும்).
- **Rate limits:** Bot ஒன்றுக்கு global cap 50 requests/second; individual routes-க்கு own (often shared/bucketed) limits `X-RateLimit-*` response headers வழியா தெரியும் — docs-ல் limits-ஐ hard-code பண்ணாம headers படிக்கச் சொல்றாங்க. 10 நிமிடத்துக்கு 10,000 invalid (401/403/429) requests வந்தா IP-level protection kick ஆகும்.
- **Cost:** Free. Paid tier தேவையில்ல.
- **முக்கிய Gotchas:** File size caps உண்டு (boost இல்லாத servers-க்கு 8MB, boosted servers-க்கு அதிகம்) — "optional image" பெரிசா இருந்தா relevant. Discord-ல் page/profile concept இல்லாததால், "Discord-க்கு post பண்றது" என்றால் அர்த்தம் நீங்க already control பண்ணும் ஒரு specific server-ன் specific channel-க்கு post பண்றது — dashboard-க்கு channel ID தேவை (bot ஏற்கனவே அங்க invite ஆகியிருக்கணும்).

## Facebook Page — Meta Graph API

- **Official docs:** https://developers.facebook.com/docs/pages/publishing மற்றும் https://developers.facebook.com/docs/permissions (இந்த session-ல் domain fetch block; கீழே உள்ளது இந்த pages-ஐ quote பண்ணும் search snippets மற்றும் நெருக்கமான Meta doc pages-ல் இருந்து — உதா. `developers.facebook.com/documentation/pages-api`).
- **Auth method:** OAuth2, முடிவில் long-lived **Page Access Token** கிடைக்கும். Setup: developers.facebook.com-ல் Meta developer account + "Business" type app create பண்ணு, **Facebook Login**/Pages product add பண்ணு, Page permissions-உடன் User Access Token generate பண்ணு, அதை உங்க specific Page-க்கான Page Access Token-ஆ exchange பண்ணு. Target Facebook Page-ஐ நீங்க already administer பண்ணனும்.
- **Approval/review process:** **ஆம்.** Publish பண்ண `pages_manage_posts` (+ dependencies `pages_read_engagement`, `pages_show_list`) Advanced Access-ல் தேவை — அதுக்கு (a) Meta **App Review** (ஒவ்வொரு permission-க்கும் screencast-based submission, use case காட்ட வேண்டும்), (b) Meta Business Manager வழியா **Business Verification** (legal documents, domain verification, சில நேரம் phone call). Search-derived estimates: **App Review-க்கு ~1–3 வாரங்கள்** (initial 5–10 business days, resubmission-ல் வேகமா), Business Verification தனி timeline-ல் run ஆகும்; end-to-end **2–4+ வாரங்கள்** budget பண்ணுங்க, பல permissions-க்கு resubmission வேண்டி வந்தா இன்னும் அதிகமாகலாம். **முக்கிய Exception:** உங்க app touch பண்றது உங்க app/Business-ல் roles இருக்கும் Pages-ஐ மட்டும் என்றால், full review இல்லாமலே **Standard Access**-ல் permissions use பண்ணலாம் — இது exact OmniSocial single-user scenario, ஆகவே review initial-ல தவிர்க்கலாம், ஆனா Meta-ன் own guidance படி உங்க app roles-ல் இல்லாத எந்த Page-ஆவது manage பண்ணும் நிமிடம் full review தேவைப்படும். இதை நம்பும் முன் உங்க Meta App Dashboard-ல் current Standard-vs-Advanced-Access thresholds-ஐ confirm பண்ணுங்க.
- **Publish endpoint(s):** Text-only: `POST /{page-id}/feed` with `message`. Photo-உடன்: `POST /{page-id}/photos` image file + `caption` (text-ஆ செயல்படும்). Page Access Token தேவை, user token இல்ல.
- **Delete endpoint:** `DELETE /{post-id}` (Page Access Token-உடன்) — supported.
- **Metrics/stats endpoint:** `GET /{post-id}/insights` — `post_impressions`, `post_impressions_organic`, `post_engaged_users`, `post_clicks`, reaction breakdowns (`post_reactions_by_type_total` போன்றவை — `pages_read_engagement` + `read_insights` தேவை). Comment/share counts/lists `/{post-id}/comments` மற்றும் post object-ன் `shares` field வழியா கிடைக்கும்.
- **Rate limits:** Page publishing volume-க்கு இந்த pass-ல் single fixed public number கிடைக்கல; Meta per-app/per-user throttle பண்றது dynamic "Business Use Case" usage score வழியா (response headers-ல்), flat requests/hour figure இல்ல. Single-user, day-க்கு few-posts scale-ல் practical constraint ஆக வாய்ப்பு மிக குறைவு.
- **Cost:** Graph API use பண்ண free; இந்த scale-ல் உங்க Page data post/read பண்ண paid tier தேவையில்ல.
- **முக்கிய Gotchas:** இந்த API வழியா post பண்ண ஏற்கனவே ஒரு Facebook Page நீங்க own/administer பண்ணணும் (personal profile-க்கு post பண்ண முடியாது). இந்த 3 Meta-owned platforms-லும் (Facebook, Instagram, Threads) delay/friction-க்கு #1 காரணம் Business Verification தான் — மூணும் likely ஒரே Meta app-ல் இருந்து permissions கேட்கும், ஆகவே தனித்தனியா 3 verifications பண்றதுக்கு பதிலா ஒரே verification effort-ல் மூணையும் unblock பண்றது நல்லது.

Docs/search findings படி: non-ad posts, stories, reels, முழு carousel albums-க்கு supported; carousel-ல் ஒரு image மட்டும் delete பண்ண முடியாது — முழு carousel container-ஐ மட்டும் தான். ## Reddit — Official API (OAuth2)

- **Official docs:** https://www.reddit.com/dev/api (இந்த specific URL இந்த session-ல் நேரடியா fetch பண்ண முடியல — tool unreachable-ஆ report பண்ணுச்சு — கீழே உள்ளது Reddit-ன் developer platform pages மற்றும் 2023 API pricing/terms changes-ஐ reference பண்ணும் search-engine results-ல் இருந்து).
- **Auth method:** OAuth2. Setup: Reddit-ல் login பண்ணு, `reddit.com/prefs/apps`-க்கு போய், "create app" click பண்ணு, type **"script"** தேர்ந்தெடு (single-user server-side integration-க்கு correct — உங்க own account-உடன் நேரடியா tied `client_id`/`client_secret` கிடைக்கும், தனி user-authorization flow தேவையில்ல), redirect URI set பண்ணு (உதா. script apps-க்கு `http://localhost:8080` வேலை செய்யும்), save பண்ணு. ஒவ்வொரு request-உம் `platform:app_id:version (by /u/yourusername)` format-ல் descriptive `User-Agent` header அனுப்ப வேண்டும் — Reddit generic/default user agents-ஐ reject பண்றது.
- **Approval/review process:** இங்க use பண்ணும் free/non-commercial hobby tier-க்கு **இல்ல** — personal use script apps create ஆன உடனே வேலை செய்யும். Reddit-ன் 2023 pricing overhaul **high-volume commercial** use-ஐ மட்டும் தான் affect பண்றது (தனி application, contract pricing, தனி review) — single-user dashboard scale-க்கு applicable இல்ல, ஆனா usage grow ஆனா அல்லது இது commercial-ஆ scale-ல் resell பண்ணப்பட்டா நினைவில் வெச்சுக்கோங்க.
- **Publish endpoint(s):** `POST /api/submit` with `sr` (subreddit), `kind` (`self` text-க்கு, `link` URL-க்கு, image-post kind வேறொண்ணு), `title`, body text அல்லது URL. Reddit image posts — ஏற்கனவே host ஆன image URL-க்கு link post (எளிதானது, Instagram-க்கு use பண்ணும் "Vercel Blob public URL" pattern-க்கு fit ஆகும்) அல்லது Reddit-ன் own media upload/lease flow (native image posts-க்கு) — link-post route implement பண்ண எளிது, extra API surface தவிர்க்கலாம்.
- **Delete endpoint:** `POST /api/del` post-ன் `id` (fullname, உதா. `t3_xxxxx`)-உடன் — உங்க own content-க்கு மட்டும் supported.
- **Metrics/stats endpoint:** ஆம் — post-ஐ fetch பண்ணா (listing அல்லது `/api/info` வழியா) `score`/`ups`, `downs` (Reddit-ன் fuzzing-ஆல பெரும்பாலும் obfuscated), `num_comments` கிடைக்கும்.
- **Rate limits:** Free/non-commercial tier-ல் OAuth client ஒன்றுக்கு ~100 queries/minute (QPM), ~10 minute window-க்கு average (bursts tolerate ஆகும்); OAuth இல்லாம use பண்ணா ~10 QPM (இங்க OAuth கட்டாயம் என்பதால் applicable இல்ல).
- **Cost:** இந்த use case-க்கு (personal/non-commercial, low volume) free.
- **முக்கிய Gotchas:** இந்த set-ல் API technicality-ஐ தாண்டி genuine **community-level gatekeeping** இருக்கும் ஒரே platform Reddit தான்: individual subreddits பொதுவா தங்க சொந்த account-age (சில நாட்கள் முதல் வாரங்கள் வரை informally referenced) மற்றும் karma minimums கேட்கும், Reddit-ன் spam systems புது accounts-ஐ API access இருந்தாலும் throttle பண்ணும். அதனால் "எந்த subreddit(s), posting Reddit account already established-ஆ இருக்கா" என்பது ஒரு real prerequisite — API key மட்டும் இருந்தா போதாது, brand-new/low-karma account-ல் posts AutoModerator rules-ஆல automatically remove ஆகலாம், Reddit API அதை முன்கூட்டியே warn பண்ணாது.

Single-user, day-க்கு few-posts scale-ல் இது binding constraint இல்லவே இல்ல (day-க்கு ஆயிரக்கணக்கான creates budget-க்குள் வரும்).

- **முக்கிய Gotchas:** Bluesky/AT Protocol ஒரு genuinely open, இன்னும் evolve ஆகிட்டிருக்கும் spec — பழைய platforms-ஐ விட இங்க அதிக churn எதிர்பாருங்க (உதா. OAuth-vs-app-password transition). Images plain URL-ஆ இல்லாம blobs-ஆ upload பண்ணி hash/size/mime வழியா reference பண்ணணும் — Instagram/Reddit-ன் "public URL-ஐ point பண்ணு" pattern-ஐ விட கொஞ்சம் வேற mental model.

## Mastodon — REST API

- **Official docs:** https://docs.joinmastodon.org/client/intro/, https://docs.joinmastodon.org/methods/statuses/, https://docs.joinmastodon.org/api/rate-limits/ (direct fetch block; content official docs-ன் own GitHub source `mastodon/documentation` வழியா verify பண்ணப்பட்டது, raw GitHub content — paths `content/en/client/token.md` மற்றும் equivalent status/rate-limit pages).
- **Auth method:** OAuth2, **ஒவ்வொரு instance-க்கும் தனியா register** பண்ணணும் (இதுதான் federation-specific part — single global Mastodon app registry கிடையாது). Setup: `POST https://<your-instance>/api/v1/apps` with `client_name`, `redirect_uris` (manual/local flows-க்கு `urn:ietf:wg:oauth:2.0:oob` use பண்ணலாம்), `scopes` (உதா. `read write push`) → `client_id`/`client_secret` கிடைக்கும்; பிறகு `POST /oauth/token` bearer `access_token` பெற. `GET /api/v1/apps/verify_credentials` வழியா verify பண்ணலாம்.
- **Approval/review process:** Platform-wide-ஆ இல்ல — Mastodon-the-protocol-க்கு app review process கிடையாது. ஆனா Mastodon federated ஆனதால், **நீங்க register பண்ணும் specific instance/server தன் own signup/app rules வைக்கலாம்** (சில instances account create பண்ணவே manual approval கேட்கும், அல்லது bot-like posting-ஐ restrict பண்ணும்) — இது API technicality இல்ல, per-instance policy question.
- **Publish endpoint(s):** முதலில் image: `POST /api/v1/media` file-உடன், media attachment ID கிடைக்கும் (instance asynchronously process பண்ணா சிறு poll தேவைப்படலாம்); பிறகு `POST /api/v1/statuses` with `status` (text) + `media_ids[]` (uploaded attachment(s)-ஐ reference பண்ணி). `write:statuses` scope தேவை (upload step-க்கு `write:media`-உம்).
- **Delete endpoint:** `DELETE /api/v1/statuses/:id` — supported; response-ல் "delete and redraft" UX-க்கு போதுமான original content/media info இருக்கும்; optional `delete_media` query param attached media-ஐயும் உடனே purge பண்ணலாம்.
- **Metrics/stats endpoint:** ஆம், எந்த read-லும் return ஆகும் Status object-ல் நேரடியா: `replies_count`, `reblogs_count`, `favourites_count`. யார் react பண்ணாங்கன்னு detailed lists `/api/v1/statuses/:id/favourited_by` மற்றும் `/reblogged_by` வழியா கிடைக்கும்.
- **Rate limits:** Documented **default** — app/token ஒன்றுக்கு 5-நிமிட window-க்கு 300 requests, + per-IP 5 நிமிடத்துக்கு 7,500 requests ceiling — ஆனா Mastodon federated software என்பதால், **ஒவ்வொரு instance admin-உம் இந்த defaults-ஐ மாத்தலாம்**, ஆகவே இந்த numbers நீங்க target பண்ணும் instance-க்கு மட்டும் தான் applicable.
- **Cost:** Free — API-க்கு paid tier இல்ல; ஒரே cost consideration உங்க தேர்ந்தெடுத்த instance join பண்ண free-ஆ இருக்கா (அல்லது சொந்த instance self-host பண்ணா infrastructure cost) — இது API-focused scope-க்கு வெளியே.
- **முக்கிய Gotchas:** "Mastodon" ஒரே ஒரு service இல்ல — compatible software run பண்ணும் ஆயிரக்கணக்கான independently-run instances/servers, ஆகவே **OmniSocial account/app எந்த instance-ல் register பண்றது** என்பதே ஒரு முடிவு (உதா. mastodon.social vs சிறிய instance vs self-hosted instance), மற்றும் behavior (rate limits, signup rules, moderation policy, API version/feature availability கூட) instance-க்கு instance கொஞ்சம் மாறலாம். இந்த integration-க்கு ஒரு specific instance-ஐ pick பண்ணி, அதன் docs/behavior-ஐ உங்க deployment-க்கு authoritative-ஆ treat பண்ணுங்க.
